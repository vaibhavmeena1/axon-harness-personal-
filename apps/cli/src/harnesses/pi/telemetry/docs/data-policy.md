# Data policy

## Attribution

Every record carries `user.id` and `pi.identity.source`. In **environment fallback**, raw effective Git email is used for both `user.id` and `user.email` when available; otherwise `user.id` is a random installation UUID and `user.email` is absent. No name is automatically read from Git.

In **managed proxy mode**, the extension does not read Git email. It sends a placeholder identity (`user.id=managed`, `pi.identity.source=deputydev_auth`), and the backend overwrites resource and record/datapoint identity with verified auth-service data before forwarding. `user.id` is the authenticated user ID when present, otherwise verified email; `user.email`, optional `user.name`, and `deputydev.user_team_id` come from that same authenticated session. Client-supplied `user.*` and `enduser.*` attributes are removed, including identity fields on span events/links and metric exemplars. Missing verified identity fails closed.

The saved session is used only as the backend request Authorization header, never as an OTEL attribute. Exporter response rotation is compare-and-swap persisted without overwriting newer logins. Verified email/name are personal data: restrict collector access and retention. Authentication establishes attribution, not the truth of caller-supplied usage/cost measurements.

Identity is duplicated as a metric datapoint attribute because some metrics backends do not expose resource attributes as queryable labels. This intentionally creates one metric series per user and must be covered by organization retention and access policy.

## Repository identity

`pi.repo.slug` is derived from the `origin` remote and normalized to `host/org/repo` (lowercase host; scheme, port, embedded credentials, and `.git` removed; GitLab subgroups kept). Local paths, `file:` remotes, and repositories without an `origin` produce no slug. The raw remote URL is never exported.

The slug names private repositories and self-hosted Git hosts. It is present on spans, logs, and activity metrics (sessions, interactions, runs, turns, waits, inputs, interventions) but deliberately not on token, cost, LLM, or tool metrics, which already carry provider, model, or tool dimensions.

`pi.session.parent_id` is recorded when pi was started from another pi session's tool shell (pi injects `PI_SESSION_ID` into tool environments), so subagent activity can be joined to its parent.

## Never collected

- prompt, completion, or system-prompt text;
- image data;
- file contents or tool results;
- provider request payload contents;
- request or environment headers;
- credentials and environment values;
- full session file paths;
- raw Git remote URLs;
- extension or tool file paths (only `builtin`/`sdk`/`extension` and the scope are exported);
- stack traces.

The extension measures prompt length, image count, context-window token counts, tool-input size, and tool-output text length and image count without retaining those payloads. Image bytes are never read.

## Paths

Paths inside `ctx.cwd` are converted to slash-separated project-relative paths. Paths outside the project become `<external>/<basename>`. Home and project prefixes inside free-form summaries become `<home>` and `<project>` (home is resolved through `os.homedir()`, so Windows profiles are covered).

## Shell commands

Agent `bash`/`powershell` tool arguments and user `!` commands may include:

- executable name;
- original character count;
- a maximum 256-character redacted summary.

The sanitizer replaces bearer tokens, credentials embedded in URLs, common secret assignments/flags, private-key blocks, project/home prefixes, and remaining absolute paths. Pattern matching is defense in depth, not a proof that arbitrary secrets can never appear. Avoid broadening this policy without a data review.

## Tools

| Tool | Exported input summary |
|---|---|
| `read`, `write`, `edit`, `ls` | Input byte size and sanitized path |
| `find`, `grep` | Input byte size, sanitized path, pattern length |
| `bash`, `powershell` | Input byte size and sanitized command summary |
| Unknown/custom | Input byte size and up to 20 sorted top-level key names; no values |

Every tool span also carries the result's text character count and image count, the tool's provenance class and scope, and any nested LLM usage the tool reported (as `pi.usage.source=tool` metrics). Tool results themselves are never exported. Failed tools receive the stable classification `tool_execution_error` and a bounded message generated by the extension; raw tool output is not inspected for logging.

## Errors

Provider and compaction errors may include a maximum 256-character sanitized message. Stack traces are excluded. Export-failure diagnostics written to stderr (never in TUI mode) include a sanitized, 200-character error cause.

## Operational identifiers

Session IDs, parent session IDs, tool call IDs, trace IDs, provider request IDs, and provider response IDs appear only on traces/logs, not metric dimensions. Model, provider, tool name, tool source, usage source, outcome, mode, repository slug (activity metrics only), and user ID are metric dimensions.
